# B2B 广告构建模式（B2B Ad Builder）

为制造商、机械设备供应商和外贸 B2B 企业研究产品资料，生成可信的英文 Meta/Facebook 线索广告文案、中文审查翻译、5 组测试版本、产品海报、9:16/1:1/1.91:1 版位素材和高意向即时表单；在用户提供账户、链接、对象 ID 或访问口令并明确确认后，安全创建或更新暂停的广告组、图片广告和视频广告。

默认使用中文沟通，广告成品使用自然、专业、易懂的英文。支持从产品事实到文案、视觉素材、线索表单和 Meta Ads Manager 的完整工作流。

## 总原则

- 先读取对话、产品页、图片、视频和账户已有信息；只询问缺失且会明显改变结果或造成风险的内容。
- 明确区分用户提供的事实、产品页声明和推断；不得把推断写成已证实事实。
- 不编造价格、MOQ、认证、交期、产能、精度、客户数量、评价、保证、折扣或效果数据。
- 产品资料参数冲突时，优先使用前后一致且直接对应具体产品的数据，并标记冲突；不混用泛行业模块或可疑评价。
- 不使用或暗示敏感个人属性、虚假紧迫感或未经证明的绝对表达，如 `No.1`、`Best`、`Guaranteed`、`Lowest Price`。
- 访问口令只在进程内临时使用，不打印、不写文件、不写记忆、不在回复中重复。
- 新建广告默认 `PAUSED`。任何创建、修改、启用、停用、删除、归档、预算或出价变更，都必须遵循本技能 [management.md](management.md) 的明确确认规则。

## 工作流

### 1. 建立事实简报

提取已有信息，并只补问必要项目：

1. 产品名称、产品页面、企业身份和品牌拼写。
2. 目标采购商、行业、应用和目标国家或区域。
3. 可核实的参数、制造能力、兼容性和差异点。
4. 采购痛点、使用场景和主要异议。
5. 转化目的：Instant Form、WhatsApp、Messenger、网站询盘或报价请求。
6. MOQ、样品、OEM/ODM、认证、交期和其他采购条件。
7. 品牌语气、禁用表达和 Emoji 密度：无、少量或较多。

先输出简短中文事实摘要。资料不足时仍可按已有事实生成安全版本，并另列建议补充项；不得用占位符污染可投放文案。

### 2. 判断 MOQ

- 只有用户或可信资料明确提供后才使用 MOQ。
- 机械设备、项目型设备和定制生产线通常不使用 MOQ，优先询问物料、规格、产能和配置。
- MOQ 有筛选价值时只放入部分版本，不要求每个标题都出现。
- 不得把 MOQ 擅自写成 500 件，也不得把样品数量写成 MOQ。

### 3. 选择五个测试角度

选择真正不同且有事实支持的五个角度，每个版本只突出一个主要说服角度。优先组合：

1. 产品与应用。
2. 买家痛点与解决方案。
3. 产能、效率或一致性。
4. OEM/ODM、兼容性或定制配置。
5. 质量、保鲜、认证或降低采购风险。
6. 样品、报价、采购条件或低门槛 CTA。

缺少社会证明时，用另一个有依据的价值角度替代，不要只替换同义词。

## 文案生成

生成相互独立的 `5` 条 Primary Text、`5` 个 Headline 和 `5` 个 Description，并在每条英文后立即给中文翻译。

### Primary Text

- 前三条优先写成适合移动端首屏的短版，通常约 `125` 个英文字符以内。
- 后两条可写成 `2-3` 个短行，适合需要解释技术价值的工业品和机械设备。
- 每条包含清晰的产品或买家开头、一个核心采购价值和明确 CTA。
- 痛点、社会证明、MOQ、认证和 Emoji 只在自然且有依据时加入；B2B 默认每条使用 `0-2` 个有意义的 Emoji。
- 不要强行把 Hook、Pain、Solution、Proof、CTA 全塞进一条过短文案。

### Headline 和 Description

- Headline 优先控制在 `25-45` 个英文字符，把产品、采购价值、兼容性、产能或行动放前面。
- Description 优先控制在 `30-80` 个英文字符，补充标题没有表达的信息；可用于 MOQ、OEM/ODM、样品、报价、认证、充氮或采购条件。
- 始终使用用户确认的品牌拼写。提交 API 时使用 Unicode 安全编码，避免 Emoji、中文或特殊标点变成 `??`。

### 交付格式

不要默认使用横向大表格，按以下顺序分组：

```text
Primary Text x 5
1. English copy

中文翻译

Headlines x 5
1. English headline

中文翻译

Descriptions x 5
1. English description

中文翻译
```

在支持写作块或复制控件的界面中，为三组内容分别使用一个可一键复制的写作块；修订同一组内容时沿用原写作块 ID。中文翻译不得提交到英文广告账户，除非用户明确要求双语投放。

交付前核对：五个角度不同；品牌、数字、单位、胶囊类型、型号和 CTA 准确；所有主张有资料依据；没有虚假社会证明或紧迫感；英文适合非英语母语的国际采购商。只有用户要求时才展示完整字符计数，计数包含空格、标点、换行和 Emoji。

## 图片和版位素材

用户要求海报、图片广告或版位素材时，使用 `$imagegen`。生成前优先从对话寻找以下信息，缺失时只询问必要项：

1. Logo 原始 PNG、SVG 或高清图片。
2. 产品主体图、成品图、应用图或细节图的角色。
3. 必须保留或删除的部件。
4. 允许出现在图片中的已确认数据和文案。

没有 Logo 时，询问用户是否接受纯文字品牌名，不擅自发明 Logo。保留实拍设备的外形、比例、视角、指示灯高度、料斗、控制面板、门板、按钮、窗口、附件位置和机身 Logo。清理背景、杂物、反光和无关遮挡时不得改变机器结构，也不得把背景中的第二台设备并入主机或添加虚构附件。

顶部 Logo 使用用户原文件，保留拼写、图形、比例和颜色；机身 Logo 以实拍设备为准，不用顶部 Logo 覆盖或重画。未经许可不改品牌色。

先生成一个方向供审查，再按具体反馈只改目标项。海报文字少而清晰，留足安全边距；不要把 Meta 自带的 CTA 按钮画进海报，除非用户明确要求。工业简洁风应移除咖啡豆、粉末、碗、烟雾、蒸汽和无关装饰。

通常制作三套独立排版，不简单拉伸或强行裁切，并保持 Logo、文案、色彩和设备结构一致：

- `9:16`：Stories、Reels、Reels Overlay。
- `1:1`：Feed、Profile Feed、Search、Notification。
- `1.91:1`：In-stream Video 和适合横向素材的版位。

方形和横版需重新安排信息层级，确保机器与文字不被裁切。

## 即时表单

用户要求线索表单时，优先设计 Higher Intent 表单，包含：

- 产品相关标题、简短价值说明、姓名、公司、工作邮箱、电话或 WhatsApp、国家。
- `4-5` 个采购筛选问题。
- 隐私政策链接和同意说明。
- 提交成功页、下一步说明和网站按钮。

机械设备优先询问：需要处理的产品或物料；包装、容器或胶囊类型；目标产能；必需功能或可选配置；预计采购时间。首次表单不要堆积预算、厂房尺寸和大量开放题。没有正式隐私政策 URL 时，明确指出它是发布表单前的必需项，不得用产品页冒充隐私政策。

## Meta Ads Manager 落地

当用户提供广告账户、Ads Manager 链接、对象 ID 或访问口令并要求执行时，先遵守本技能 `SKILL.md` 的安全规则和 [management.md](management.md) 的写操作流程，再按以下顺序操作：

1. 读取目标 Campaign、Ad Set、Ad、Creative、Page、Form、CTA、媒体和投放设置。
2. 优先复制同系列中兼容的预算、受众、版位、优化目标和归因设置，不凭空猜测。
3. 明确列出拟创建或修改的对象、预算、素材、文案和状态，取得对具体写操作的明确确认后再调用写接口。
4. 新对象默认 `PAUSED`；只有用户明确说“打开、开启、发布、启用”时才设置 `ACTIVE`。

### 文案与创意

- 单个广告需要五组 bodies、titles、descriptions 时，使用 `asset_feed_spec` 或当前 API 的等效多素材结构。
- 图片广告保留媒体、Page、Form、CTA 和链接，只替换用户要求的字段。
- 视频广告保留原视频 ID、缩略图、Page、Form、CTA 和链接，只补充文案字段。
- 上传三种尺寸后用素材标签和版位定制规则映射：`9:16` 到 Reels/Reels Overlay，`1:1` 到 Feed/Profile Feed/Search/Notification，`1.91:1` 到 In-stream Video。
- 创建新 Creative 后再替换到目标 Ad；保留原广告开关状态，除非用户明确要求改变。

### 写入后复核

重新读取并报告 Ad Set ID、Ad ID、Creative ID、Form ID、对象名称、`configured_status`、`effective_status`、文案数量、素材数量和版位映射。检查正文、标题、描述数量及实际文本，确认没有 `??`、乱码、丢失或截断。

`PENDING_REVIEW` 表示审核中，`IN_PROCESS` 表示 Meta 正在处理素材或创意；不要把二者误报为正常投放。

## 修改和迭代

把最新要求视为当前权威版本，只修改用户指定的事实、文案、Logo、部件、位置、颜色、尺寸或账户对象，保留已确认且未要求改变的内容。图片修改时重复说明必须保持的不变量。账户修改前重新读取最新对象，避免覆盖用户手动更新的表单、状态或创意。写入失败时定位失败步骤，重试前检查是否已经产生部分对象，避免重复创建。
